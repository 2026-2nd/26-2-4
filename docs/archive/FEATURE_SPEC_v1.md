# 거래별 Feature 명세 v1.3

작성일: 2026-11-02. 보관·검토 항목은 24개이나 기본 입력 후보는 13개(아파트 특성 10개+지역·시간 통제 3개)로 축소했다. 나머지는 대체 사양·산출·보조 분석용이다. 구축 상태는 각 변수별 기록을 참조한다. 실제 상관관계·VIF 계산과 모델 학습은 수행하지 않았다.

사용자 승인 범위 변경: 단지 내부 4개 변수는 별도의 안정성 가정 적용본에서 현행값을 소급할 수 있다. 동일 단지·준공 조건, 원천값 유효성, 알려진 변경 위험 제외 조건을 적용하고 assumed_time_invariant를 기록한다. 과거 동수·실제 속성 불변은 입증되지 않았다. 엄격한 역사값과 혼합 표시하지 않으며 원 엄격 데이터는 보존한다. 상세: reports/internal_static_assumption/안정성가정_검토와_결측감소.md. 역·학교 등의 실제 날짜 규칙은 그대로 유지한다.

## 시장 변수 축소 결정

사용자 연구 의도는 어떤 아파트 특성이 수요와 가격에 연결되는지 살펴보는 것이다. 과거 가격·상승률·가격지수로 예측을 대신 설명하지 않도록 관련 변수 9개를 현행 후보에서 제외했다. 중복 축소 후 기본 분석은 교통·교육·단지 내부·호실 특성 10개와 지역·시간 통제 3개로 구성한다. 거래량 1개는 보조 분석 후보이며 기본 입력에는 넣지 않는다. 지역 통제 역시 입지 차이를 흡수할 수 있으므로 통제 유무에 따른 중요도 민감도를 함께 확인한다.
수요는 현재 자료에서 직접 관측되지 않는다. 거래량은 수요와 공급·매물·거래 제약이 함께 반영된 성사량이다. 아파트 특성→수요→가격이라는 경로는 가능한 연구 해석 틀이며, 현재 회귀 예측·SHAP만으로 이 경로나 매개효과를 입증하지 않는다. 수요 경로를 살피려면 별도의 수요 측정과 인과적 식별 설계가 필요하다.

## 중복·공선성 관리 결정

| 기본 유지 | 기본 입력에서 제외·별도 보관 | 이유 |
|---|---|---|
| 최근접 운영역 거리 + 고유 노선 수 | 역 수·환승역 거리 | 접근성과 노선 선택 폭만 대표로 두고 유사 교통 지표 축소 |
| 최근접 초등학교 거리 | 초·중·고 학교 수 | 접근성 대표 1개로 시작. 학교급별 정보가 동일하다고 단정하지 않음 |
| 총세대수 | 동수 | 단지 규모 대표 선택 |
| 세대당 주차대수 | 총주차대수 | 규모와 주차 여건 분리. 총주차는 비율 산출용으로 보관 |
| 거래층 | 상대층·단지 최고층 | 상대층은 정확한 동 정보 확보 후 거래층을 대체하는 실험으로 분리 |
| 거래 당시 연식 | 건축연도·사용승인연도 원값 | 계약시점과 함께 원연도를 입력하면 연식과 결정적 관계 발생 |
| 난방방식·복도유형 | 건물구조 | 연식과의 연관은 추후 범주형 진단. 난방·복도는 서로 다른 속성이므로 우선 유지 |

실제 데이터 진단은 별도 후속 작업이다. 수치형 Pearson·Spearman 상관, 범주형 연관 및 연식에 따른 범주 분포를 살핀다. 선형모형용 설계행렬은 절편과 k-1 더미 등으로 완전 종속을 제거한 뒤 VIF를 참고한다. |상관|≥0.85 또는 VIF>5는 검토 표시용 운영 기준으로 두고 자동 삭제하지 않는다. 쌍별 상관만으로 다변량·비선형 중복이 해소됐다고 판단하지 않는다.
동일 단지의 많은 거래가 진단을 지배하지 않도록 거래행 기준과 단지·시점 단위 요약 기준을 함께 비교한다. 변수 선택·임계값 조정은 추후 Train 안에서만 수행하고 Test는 사용하지 않는다. 유지/대체는 측정 신뢰도·시점 이력·결측률·연구적 의미와 검증기간 성능/중요도 안정성을 함께 고려한다. 연식과 난방의 연관처럼 의미 있는 서로 다른 특성은 상관만 보고 기계적으로 삭제하지 않는다. 트리도 상관변수 간 중요도가 분산될 수 있으므로 중요도 안정성을 확인한다.

## 1. 데이터 구성 원칙

한 행은 아파트 매매 거래 1건이며 계약일이 기준시점 t다. 모든 Feature는 해당일 유효한 상태 또는 해당일 이전 이용 가능 정보에서 계산한다. 공원·자연환경 변수는 제외한다. 거래가 없는 아파트를 새 거래처럼 추가하지 않는다. 현재 거래자료는 최신 수정본이므로 완전한 당시 정보가용성을 보장하지 않는다.

최종 데이터는 식별·감사 필드, 아래 Feature, 별도 Target으로 구성한다. 단지명·원주소·원천 ID·좌표는 연결/감사용이며 기본 모델 입력으로 자동 포함하지 않는다. 위치 코드의 통제 역할은 별도로 보고한다.

## 2. 날짜·공간·결측 공통 규칙

- 상태 이력: valid_from ≤ t < valid_to. 종료일 NULL은 원천에서 계속 운영 중임이 확인된 경우에만 열린 구간으로 취급한다. 단순 이력 누락과 구분한다.
- 시설 개통·폐쇄·이전 등 물리적 상태와 source_published_at(공표일), retrieved_at(수집일)을 각각 저장한다. 현재 수집일을 과거 공표일로 만들지 않는다.
- 역·학교 운영은 날짜 단위 자료에서 개시일 당일부터 유효하게 처리하되 당일 시각은 구분할 수 없다는 한계를 기록한다. 계획·예정일을 실제 개시일로 대체하지 않는다.
- 거래·시장 정보는 공개시각이 없으면 보수적으로 공개일 < 계약일을 적용한다. 같은 날 거래와 현재 거래는 과거 비교집합에서 제외한다. 계약 당시 해제 이력이 없으면 strict PIT(당시 가용정보)로 표시하지 않는다.
- 과거 공표일 미확보 자료의 계약일+30/60/90일은 지연 가정 민감도 실험일 뿐 실제 공표일이 아니다. 현행 수정본 회고 분석과 strict PIT 결과를 구분한다.
- 거리 기본안: 당시 단지 대표점→시설 대표점 Haversine 직선거리(m), 평균 지구반경 6,371,008.8m. 좌표계 확인 후 경위도로 통일한다. 보행거리·출입구거리는 별도 확장이다.
- 반경은 ≤1,000m, 전국/수도권 자료에서 인접 경계 밖 시설도 포함한다. 서울 행정경계로 자르면 주변 시설 누락이 생길 수 있다.
- 수집범위 불완전·시점 이력 불명·단지 매칭 불명은 NULL+사유. 대상 시설이 없다는 사실이 완전한 범위에서 확인된 개수만 0으로 둔다. 최근접 거리는 없으면 NULL이며 0이나 임의 큰 값으로 채우지 않는다.
- 통계 최소건수·유사면적 규칙·이상거래 제외 기준은 결과에 맞춰 조정하지 않고 구현 전 별도 버전으로 고정한다. 현재 5㎡ 구간은 비교 후보일 뿐 확정 아님.
- 학습 기반 결측 대체·표준화·범주 인코딩은 추후 Train에만 적합한다. 현 단계에서 전체기간 평균으로 채우지 않는다.

## 4. 변수별 원천·결합·날짜·결측 명세

### `nearest_operating_station_distance_m` — 최근접 운영역 직선거리

- 원천: 역·노선 운영 및 위치 이력 + 단지 좌표
- 연결: complex_id→당시 단지 대표점; station_id/physical_station_id/line_id
- 날짜 적용: 운영 시작일≤계약일<운영 종료일, 위치 버전도 해당일 유효. 환승 노선은 노선별 운영일 적용
- 결측 처리: 역·단지 좌표 또는 운영 이력/대상 노선 범위가 불완전하면 NULL과 사유. 미수집을 0으로 처리 금지
- 현재 상태: 1~8호선 현행 좌표만 확보; 전체 노선·운영 이력·단지 연결 보완 필요

### `operating_station_count_1km` — 1km 내 운영역 수

## 5. 식별·품질 필드와 Target 분리

| 필드 | 용도 |
|---|---|
| record_id | 수집 스냅샷 ID+원본 파일+행번호에서 생성. 법적 거래 고유번호가 아니며 재수집 간 연결키와 구분 |
| record_fingerprint | 원천 거래 특성의 비교용 해시. 같아도 별도 거래일 수 있으므로 자동 중복 삭제 금지 |
| contract_date / source_file / source_row / retrieved_at | 계약일·원본·수집시점 추적 |
| complex_id / building_id / match_status / match_evidence | 검토된 단지·동 연결과 근거; 재건축 전후 버전 구분 |
| complex_lat / complex_lon / coordinate_basis | 당시 위치·좌표계·단지 대표점 정의. 원시 좌표는 기본 입력 제외 |
| nearest_station_id / nearest_school_id | 거리 계산 대상 추적. 식별자를 자동 모델 입력으로 쓰지 않음 |
| age_basis | exact_approval_date / build_year_approx / unknown |
| feature_name / valid_from / valid_to / source_published_at / retrieved_at / source_id | Feature별 이력과 출처를 별도 긴 형식 감사 테이블로 저장 |
| history_status / availability_status / missing_reason | confirmed / assumed / unknown / conflict 등을 구분. 시점 불확실성을 숨기지 않음 |
| cancellation_status | 수집 당시 해제 상태. 당시 상태가 따로 있으면 버전별 관리 |
| max_feature_available_at | 실제 확인된 공표일의 최댓값. 일부 정보 가용일이 미확인이면 완전성 플래그 필요 |

Target A는 거래금액(만원)이며 현재 거래가격·㎡당가격을 모델 A 입력으로 포함하지 않는다. Target B는 단지·유사면적의 실제 후행 가격창으로 계산한 3년 변화율로 별도 테이블에 둔다. 종료가격·미래 거래건수·label_available_at은 입력 Feature가 아니다. 현재 매수가격을 모델 B 입력으로 쓰는 실험은 추후 명시적으로 분리하며 기본 명세에는 포함하지 않는다.
한 단지·면적대·기준시점의 같은 상승률이 여러 거래행에 반복될 수 있다. 해당 레이블을 독립표본으로 계산하지 않도록 label_group_id를 보존하고, 평가 단위·가중치는 모델링 때 별도 결정한다. 미관측 3년 뒤 값을 생성하지 않는다.

## 6. 원천 테이블과 결합 흐름

1. 거래 테이블: 수집한 373,718행을 원본 보관. 해제 제외 356,087행은 정밀 정제 전 입력 후보이며, 계약일·주소·면적·가격 유효성 검사 후 유지/격리 사유 기록.
2. 단지 연결표: transaction complex key ↔ complex_id ↔ 원천 단지코드. 단지명 별칭·주소·유효기간·재건축 전후·검토 근거 관리. aptSeq와 kaptCode 동일 취급 금지.
3. 단지 상태 이력: complex_id/building_id, 속성별 valid_from/to, 값, 근거, 공표일. 모든 속성이 같은 시점에 변경됐다고 가정하지 않음.
4. 역·노선 이력: 물리적 역/역 버전/노선 연결을 분리하여 환승역 중복과 노선별 개통시점 처리.
5. 학교 캠퍼스 이력: 학교ID·학교급·캠퍼스 위치·실제 운영기간·이전 이력 관리.
6. 과거 거래: 보조 분석이 필요한 경우에만 거래건수 후보를 검토한다. 공개일·해제 이력으로 당시 관측 가능한 비교집합을 구성하며 계약일만 있는 결과는 availability_assumed/unknown으로 구분한다. 과거 가격·상승률·지수 Feature는 생성 범위에서 제외한다.
7. 거래별 Feature 테이블과 긴 형식 감사 테이블을 생성. Target·이력 불확실 데이터는 별도로 관리.

## 7. 완료 판정 및 다음 실행 순서

완료 판정: 출력 거래 record_id가 유일하고, 의도치 않은 다대다 결합으로 행수가 늘지 않아야 한다. 제외·격리 전후 행수와 사유를 합산해 원본과 대조한다. 모든 생성값에 출처와 날짜 적용 근거가 있어야 하며, 미확인 이력은 현재값으로 채우지 않는다. 연도·자치구·단지 크기별 매칭률·시점확인률·결측률을 공개한다. 역 개통/학교 이전 전후 경계일을 점검한다. 가격·미래 정보의 입력 혼입을 차단한다.
다음 실행은 서울 전체 거래의 기본 정제 및 단지 연결표 구축이다. 그다음 P1 원천 이력의 확보율을 조사하고 확인된 변수부터 거래별로 결합한다. 자료가 없으면 사용자에게 근거와 제외/근사 대안을 제시한다. 본 문서 작성 과정에서 추가 대량 수집·Feature 실제 생성·모델 학습은 하지 않았다.

기존 Phase 1 데이터 사전은 pilot 산출물 기록이다. 향후 최종 Feature의 정의는 이 명세와 `config/feature_spec_v1.json`을 기준으로 버전 관리한다.
